# Demo test: Chain EAL vs Sample Tree EAL (small-scale)

Short A/B run to check whether **Sample Tree EAL** (`sample_rsd`) beats **Chain EAL** (`al_tv`) before a full train.  
Wall-clock target: **tree ≤ ~1 hour** on 3× A6000.

This folder records **what was trained**, **how it was evaluated**, the **train/test splits**, and the **numbers we got**.

---

## TL;DR result

Trained on a 2048-example Alpaca-regen subset (**A**). Evaluated under a shared **tree sample+RSD** probe (`path_topk=4`, `n_anchors=4`) on four small splits:

| Split | Meaning | Chain E[L] / path1 | Tree E[L] / path1 | Δ (tree − chain) |
|---|---|---|---|---|
| **A** | train-time val (mixed 16) | 3.56 / 2.88 | **3.79 / 3.42** | +0.24 / +0.53 |
| **B** | Alpaca holdout (same domain, not in train) | 3.28 / 2.36 | **3.63 / 3.07** | +0.35 / +0.71 |
| **C** | mixed ShareGPT-style multi-turn | 3.34 / 2.03 | **3.83 / 2.68** | +0.49 / +0.66 |
| **D** | fresh ShareGPT (disjoint from mixed_val) | 3.34 / 2.40 | **3.80 / 3.08** | +0.47 / +0.69 |

Tree wins on **all** splits (in-domain and OOD). Raw rows: [`results/ood_tree_path_probe.jsonl`](results/ood_tree_path_probe.jsonl).  
Plots: [`results/quick_chain_vs_tree.png`](results/quick_chain_vs_tree.png), [`results/quick_chain_vs_tree_top4_paths.png`](results/quick_chain_vs_tree_top4_paths.png).

## Training recipe (what we ran)

Parallel on one 4×A6000 node:

| Job | GPUs | Script | Key args | Budget |
|---|---|---|---|---|
| **Chain EAL** | GPU 0 | `sdpo/main_small_lm.py` | `--aux_loss al_tv --anchor none --sigmoid_coef 1.0 --gamma 7 --lr 1e-6 --num_epochs 2 --max_train_samples 2048` (+ optional `--tree_path_probe_every 50` for path curves) | ~20–25 min |
| **Sample Tree EAL** | GPU 1,2,3 | `sdpo/main_small_lm_tree_v2.py` | `--eal_mode sample_rsd --path_topk 4 --n_anchors 4 --anchor_chunk 2 --anchor_kl_coef 0.1 --eal_aux_coef 1.0 --num_epochs 1 --max_train_samples 2048` | ~40 min (≈683 steps × ~3.5 s/it) |

DeepSpeed: chain `sdpo/scripts/tree_eal/ds_zero2_a100_1gpu.json`; tree `sdpo/scripts/tree_eal/ds_zero2_a6000_3gpu.json`.

Orchestrator used in the eng-wl3181 run (paths point at `/mnt/ssd_ext/...`; edit `ROOT` for your machine):

```bash
bash docs/demo_test/scripts/run_quick_chain_vs_tree.sh
```

## How we measured (demo test protocol)

### 1) Fair decode-aligned probe (primary)

Both drafts are scored with the **same** tree forward:

- Mode: `sample_rsd` (sample full tree → `path_topk` prune → residual TV / RSD mass)
- `path_topk=4`, `n_anchors=4`, temperature `1.0`
- Metric: `tree_probe_eal` (E[L]) and `path{1..4}_al` (hard accept length on top draft-prob paths)

Script: `docs/demo_test/scripts/probe_chain_tree_paths.py`

```bash
# Example: probe tree ckpt on split B
CUDA_VISIBLE_DEVICES=0 python docs/demo_test/scripts/probe_chain_tree_paths.py \
  --basepath /path/to/qwen3-8b \
  --draftpath /path/to/hf_epoch_0_or_stripped_chain \
  --datapath docs/demo_test/data/quick_ood_B_alpaca_holdout.jsonl \
  --savedir /tmp/probe_out \
  --tag tree_B_alpaca_holdout --max_samples 32 \
  --path_topk 4 --n_anchors 4
```

**Important:** chain `state_*` checkpoints often store weights under a `draft_model.` prefix. Strip before HF/`from_pretrained` load (otherwise you silently get random draft weights and path AL ≈ 0). The quick runner already strips to `state_*_stripped`.

### 2) Generalization matrix (A/B/C/D)

After training, run the probe for **chain** and **tree** on splits A–D (32 examples each except A=16).  
This is the “train on A, test on B/C/D” check.

### 3) Plots (optional)

```bash
python docs/demo_test/scripts/plot_profile_chain_vs_tree.py \
  --root /path/to/checkpoints \
  --chain-tag quick_sample_chain_eal \
  --tree-tag quick_sample_tree_eal \
  --path-compare --xmax 5000 \
  --chain-gpus 1 --tree-gpus 3 \
  --out docs/demo_test/results/quick_chain_vs_tree_top4_paths.png
```

## Conclusion for go / no-go

On this small demo, Sample Tree EAL is **consistently better** than Chain EAL on:

- in-train val analytic AL,
- shared tree-path E[L] / path1,
- held-out Alpaca (**B**) and ShareGPT-style OOD (**C**, **D**).

That supports proceeding to a full-scale train with the same `sample_rsd` recipe (`n_anchors=4`, `anchor_chunk=2`, `path_topk=4`).
